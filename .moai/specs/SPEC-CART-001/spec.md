## §1. 개요

`our-shop`(모바일 우선 B2C 패션 이커머스)의 **장바구니 도메인**을 정의한다. 상품 담기·수량 변경·삭제·조회 4개 작업과, 로그인 시 게스트 장바구니를 회원 장바구니로 병합하는 로직을 다룬다.

이 저장소에는 지금까지 "게스트(비회원) 신원" 개념이 전혀 존재하지 않았다 — SPEC-AUTH-001은 회원 인증만 다뤘다. 이 SPEC이 게스트 신원을 처음 도입한다: `structure.md`가 애초에 `lib/auth/`를 "인증(회원/게스트 세션)"이라고 제안해 두었으므로, 게스트 식별 쿠키는 SPEC-AUTH-001의 인증 쿠키(`refresh_token`/`csrf_token`/`oauth_state`)와 **이름·값·수명이 전혀 다른 별도의 opaque 쿠키**로 설계한다 — 게스트는 인증 세션의 축소판이 아니라 독립적인 신원 축이다(§2.2).

이 SPEC은 SPEC-CATALOG-001/002가 구축한 `Product`(가격·재고) 모델과 SPEC-AUTH-001의 `User`/세션 검증 메커니즘 위에서 동작하지만, 두 SPEC의 파일을 직접 수정하지 않는다 — 병합 트리거는 로그인 성공 경로(`/api/auth/login`, `/api/auth/google/callback`)에 훅을 거는 **cross-cutting 통합 지점**으로만 문서화하며(plan.md §6), 실제 파일 수정은 run-phase 작업이다.

## §2. 요구사항 (GEARS, REQ-CART-001 ~ 015)

### 데이터 모델 및 불변식

- **REQ-CART-001** (Ubiquitous): 장바구니 도메인은 각 카트(Cart)를 정확히 하나의 신원(회원이면 `userId`, 비회원이면 게스트 식별자)에 귀속시켜야 하며, 카트 항목(CartItem)은 하나의 상품(Product)과 수량(quantity)을 참조해야 한다.
- **REQ-CART-002** (Ubiquitous): 카트 항목의 수량은 항상 1 이상의 정수여야 하며, 어떤 경로(담기·수량변경·병합)를 거치더라도 수량이 0 이하인 카트 항목이 영속화되어서는 안 된다 — 수량이 0으로 귀결되는 경우 해당 항목은 제거되거나 애초에 생성되지 않아야 한다.

### 신원 해석 (회원 vs 게스트)

- **REQ-CART-003** (Ubiquitous): 장바구니 서비스는 모든 카트 요청의 신원을 다음 규칙으로 해석해야 한다 — 요청이 유효한 `Authorization: Bearer` 액세스 토큰을 포함하면 인증된 사용자의 id로 해석하고, 그렇지 않으면 httpOnly 게스트 식별 쿠키로 해석하며, 쿠키가 없으면 새로 발급해야 한다.
- **REQ-CART-004** (Ubiquitous): 게스트 식별 쿠키는 httpOnly여야 하며, 암호학적으로 무작위인 opaque 값을 가져야 하고, SPEC-AUTH-001의 인증 쿠키들과는 다른 이름과 다른 수명을 가져야 한다.

### 장바구니 조회

- **REQ-CART-005** (When): 카트 조회 요청이 도착하면, 장바구니 서비스는 해석된 신원의 현재 카트 항목들(상품 정보·수량 포함)과, 각 항목 수량에 상품의 **현재** 가격을 곱해 합산한 소계(subtotal)를 반환해야 한다.

### 담기

- **REQ-CART-006** (When): 담기 요청이 유효한 `productId`와 1 이상의 정수 `quantity`를 포함하면, 장바구니 서비스는 해당 카트에 새 항목을 생성하거나(해당 상품이 카트에 없던 경우) 기존 항목의 수량에 요청 수량을 더해야 한다(해당 상품이 이미 카트에 있던 경우).
- **REQ-CART-007** (When — 이벤트 탐지형): 담기 또는 수량변경 요청이 존재하지 않는 `productId`를 참조하거나, 1 이상의 정수가 아닌 `quantity`를 포함하거나, 그 결과 해당 카트 항목의 수량이 상품의 현재 재고(`Product.stock`)를 초과하게 되면, 장바구니 서비스는 요청을 거부(400)해야 하며 어떤 변경도 영속화해서는 안 된다.

### 수량 변경

- **REQ-CART-008** (When): 수량변경 요청이 카트에 존재하는 항목과 REQ-CART-007을 통과하는 `quantity`를 지정하면, 장바구니 서비스는 해당 항목의 수량을 요청된 값으로 **절대값 설정**해야 한다(기존 수량에 더하지 않음 — REQ-CART-006의 담기와 다른 의미론).

### 삭제

- **REQ-CART-009** (When): 삭제 요청이 해석된 카트에 존재하는 항목을 대상으로 하면, 장바구니 서비스는 해당 항목을 제거해야 하며 같은 카트의 다른 항목에는 영향을 주지 않아야 한다.
- **REQ-CART-010** (When — 이벤트 탐지형): 수량변경 또는 삭제 요청이 존재하지 않거나 해석된 카트에 속하지 않는 항목을 대상으로 하면, 장바구니 서비스는 404를 반환해야 하며 다른 어떤 카트도 변경해서는 안 된다.

### 로그인 시 게스트→회원 카트 병합

- **REQ-CART-011** (When): 사용자가 게스트 카트를 보유한 상태에서 로그인에 성공하면(이메일/비밀번호 또는 Google OAuth 무관), 장바구니 서비스는 게스트 카트를 해당 사용자의 카트로 병합해야 한다.
- **REQ-CART-012** (When): 병합 시, 게스트 카트의 각 상품에 대해 — 사용자 카트에 동일 상품이 이미 있으면 두 수량을 합산한 뒤 상품의 현재 재고를 초과하면 재고로 클램프해야 하고, 사용자 카트에 없던 상품이면 게스트 카트의 수량을 그대로(단, 동일하게 현재 재고로 클램프하여) 가져와야 한다. 클램프 결과 수량이 0이 되는 상품(재고 소진)은 병합된 카트에 항목으로 남지 않아야 한다(REQ-CART-002).
- **REQ-CART-013** (When): 병합이 성공적으로 완료되면, 장바구니 서비스는 병합된 게스트 카트가 이후 그 게스트 식별 쿠키로는 더 이상 조회되지 않도록 보장해야 한다(비움·삭제·소유권 이전 등 구현 방식은 자유 — 관찰 가능한 결과만 규정) — 이는 동일 게스트 카트가 이후 로그인에서 다시 병합되는 것을 방지한다.

### 게스트 접근성 / 재고 처리 경계

- **REQ-CART-014** (Unwanted, shall not): 게스트 카트의 조회·담기·수량변경·삭제는 어떤 인증 자격 증명(Authorization 헤더 등)도 요구해서는 안 된다.
- **REQ-CART-015** (Unwanted, shall not): 장바구니 서비스는 담기·수량변경·병합 시점에 `Product.stock`을 차감하거나 예약(reserve)해서는 안 된다 — 재고는 매 요청마다 현재 값을 확인만 하는 라이브 체크이며, 실제 재고 확정/차감은 향후 체크아웃 SPEC의 책임이다.

## §3. Out of Scope

### Out of Scope — 결제/주문 (Checkout, Payment, Order Creation)
- 체크아웃 플로우, 결제(PG) 연동, 주문 생성은 이번 SPEC 범위 밖이다 — `structure.md`가 제안한 별도 `features/checkout` 도메인의 후속 SPEC 대상이다.

### Out of Scope — 가격 스냅샷/잠금 (Price Snapshot/Lock)
- 카트 항목에 담기 시점의 가격을 저장(snapshot)하거나 잠그는 기능은 이번 SPEC 범위 밖이다. 이번 SPEC은 항상 `Product.price`를 라이브 조인해 계산한다 — 결정 근거는 plan.md §2.4.

### Out of Scope — 재고 예약/잠금 (Stock Reservation/Lock)
- 담기·수량변경·병합 시점에 재고를 예약하거나 차감하는 기능(REQ-CART-015)은 이번 SPEC 범위 밖이다. 하드 재고 확정/차감은 향후 체크아웃 SPEC이 소유한다.

### Out of Scope — 장바구니 만료/정리 작업 (Cart TTL / Cleanup Jobs)
- 오래된 게스트 카트(또는 회원 카트)를 주기적으로 삭제하는 TTL/배치 정리 작업은 이번 SPEC 범위 밖이다.

### Out of Scope — 다중 통화 (Multi-Currency)
- 여러 통화 지원은 이번 SPEC 범위 밖이다 — SPEC-CATALOG-001과 동일하게 KRW 정수(Int) 단일 통화를 전제한다.

### Out of Scope — 나중에 보기 / 위시리스트 (Saved-for-later / Wishlist)
- 장바구니에서 빼서 별도로 저장하는 위시리스트/나중에 보기 기능은 이번 SPEC 범위 밖이다.

### Out of Scope — 관리자 장바구니 관리 (Admin Cart Visibility/Management)
- 관리자가 특정 사용자·게스트의 장바구니를 조회/수정하는 기능은 이번 SPEC 범위 밖이다.

### Out of Scope — 장바구니 엔드포인트 CSRF 보호 (Cart CSRF Protection)
- 게스트 쿠키 기반으로 인증되는 카트 변경 요청(담기/수량변경/삭제)에 대한 CSRF 이중 제출 토큰 등 방어는 이번 SPEC 범위 밖이다 — 카트 조작이 노출해도 PII/결제 정보 유출이나 계정 탈취로 이어지지 않는 낮은 심각도의 잔여 위험으로 판단해 명시적으로 수용한다(plan.md §2.2). 필요해지면 REQ-AUTH-023의 double-submit 패턴을 참고해 후속 SPEC에서 추가한다.
