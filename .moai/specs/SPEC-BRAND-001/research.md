### §3.3 사이즈 범위 표시 문자열 — ⚠️ 시드하지 말 것 `[전사 제공 — 합성 판정은 manager-spec 추론]`

`renderVals()`는 제품별 사이즈 범위 문자열을 **인덱스 나머지 연산으로 생성**한다:

```js
i % 3 === 0 ? "250–330mm" : "260–320mm"
```

결과: 시로코(i0)="250–330mm", 에지마(i1)="260–320mm", 노마치(i2)="260–320mm", 아키타(i3)="250–330mm", 세토(i4)="260–320mm", 하야마(i5)="260–320mm".

**이 값은 제품 데이터가 아니라 목업 채움값(placeholder)이다.** `i % 3`은 화면을 다양해 보이게 하는 전형적 렌더링 장치이며, 실제 제품 속성이 아니다. 시로코와 아키타가 같은 범위를 갖는 유일한 이유는 두 인덱스가 3으로 나누어떨어진다는 것뿐이다.

**처리 방침**: 이 문자열을 `Product` 행에 시드하지 **않는다**. 렌더링 인공물을 데이터로 굳히면, 이후 누구도 그것이 임의값이었다는 사실을 알 수 없게 된다.

**추가 불일치**: 브랜드 카피는 **"285mm부터 330mm까지"**(큰 사이즈 전문)라고 말하지만, 이 채움값들은 250mm/260mm에서 시작한다. 카피와 채움값이 서로 모순된다 — 채움값이 합성이라는 판정을 뒷받침하는 정황이기도 하다. `/bespoke` 카피(REQ-BRAND-017)는 **브랜드 카피 쪽("285mm부터 330mm까지")을 따른다**.

### §4.2 ⚠️ 전사하면 안 되는 것 2건 `[확인됨 — manager-spec이 plan-audit iter3에서 재실행 후 관찰]`

원천을 그대로 복사하면 **두 곳에서 규칙 위반이 발생한다.** 아래 두 명령은 iter3에서 다시 실행하여 출력을 직접 관찰했다.

**(1) `--color-accent-2-100..900` 램프 9개 — 추가 금지**

원천에는 `--color-accent-2-100` ~ `--color-accent-2-900` 9개 토큰이 있다(accent 램프와 값이 완전히 동일). 그러나 코드베이스 `@theme`에는 **이 이름들이 존재하지 않는다**:

```
$ grep -c 'accent-2-' src/app/globals.css
0
```

램프 접두사 `accent-2-`의 출현 횟수가 **0**이다 — 램프 9개가 하나도 없음을 직접 보여준다.

> **왜 `grep -n "accent-2"`를 쓰지 않는가** (plan-audit iter1 D1 → iter3 수정): 그 패턴은 **2줄**을 반환한다 — L50의 평면 토큰 `--color-accent-2`와, L55의 `--color-accent-200` 안에 우연히 들어 있는 부분 문자열이다. 후자는 `accent` 램프의 일원이지 `accent-2` 램프가 아니므로, 이 패턴은 "램프가 없다"는 주장의 증거로 부적합하다(부분 문자열 잡음이 결론을 흐린다). `accent-2-`는 하이픈까지 포함해 램프 접두사만 정확히 겨냥하므로 `0`이라는 출력이 곧 부재의 증명이 된다.

이 9개를 추가하면 **REQ-BRAND-007(프로퍼티 이름 집합 불변)을 위반**하고 AC-BRAND-007이 실패한다. 원천에 있다는 이유로 추가하지 않는다 — `design.md` §2.2가 예고한 "원천에만 있는 이름" 사례가 실제로 발생한 것이다.

**(2) 폰트 값의 **리터럴 문자열** — 되돌리기 금지**

원천은 `--font-heading: "Cormorant Garamond", system-ui, sans-serif;`처럼 **리터럴 폰트명**을 쓴다. 코드베이스는 다르다:

```
67:  --font-heading: var(--font-heading-nf), system-ui, sans-serif;
69:  --font-body: var(--font-body-nf), system-ui, sans-serif;
```

이 `var(--font-*-nf)` 형태는 **t51 후속 카드(CodeRabbit follow-up)가 명시적으로 승인한 의도적 이탈**이다(globals.css 57-66행 주석). `next/font`가 방출하는 CSS 변수를 참조하도록 바꾼 것이며, **렌더링되는 폰트는 동일**하다(Cormorant Garamond / Lora). 원천의 리터럴로 되돌리면 **승인된 수정을 무효화**한다.

→ 폰트 토큰 3개(`--font-heading`, `--font-heading-weight`, `--font-body`)는 **손대지 않는다**. 이 SPEC은 색상만 재조정한다.

### §5.1 위임 브리핑 대비 정정 사항

브리핑이 제시한 전제 중 **두 건이 실제 코드베이스와 달랐다**:

1. **`next/image` 사용 여부** — 브리핑은 그린필드일 가능성을 열어두었으나, **이미 두 곳에서 사용 중**이다. 따라서 `plan.md` §B.4의 렌더링 결정은 새 컨벤션 수립이 아니라 **기존 선례 준수**다.
2. **`.plate` 클래스** — 브리핑은 원천의 필터가 `sepia`에서 `grayscale`로 "변경"되었다고 기술했으나, **코드베이스에는 `.plate`가 아예 없다**. M2에서 이는 수정이 아니라 **신규 추가**다.

## §6. 목업 내비게이션 동작 — 범위 결정의 근거 `[전사 제공]`

`OUR Store.dc.html`의 내비 핸들러:

| 내비 항목 | 목업의 실제 연결 |
|---|---|
| SHOP | 리스트 화면 (`{{ goList }}`) |

## §7. UI Kit 컴포넌트 목록 `[전사 제공]`

`OUR UI Kit.dc.html`에 정의된 컴포넌트:

- 버튼 (주문/장바구니/사이즈 안내 CTA — 한글+영문 병기 라벨)
- 상품 카드 (이름 + 한글/로마자 부제 + 가격; 품절 상태는 **불투명도 62% + 태그 오버레이**)
- 사이즈 선택기 (5열 그리드; 선택 시 `btn-primary`, 미선택 `btn-secondary`, 품절 사이즈 `disabled`)
- 가죽/소재 라디오 쌍
- 수량 스테퍼
- 주문 요약 카드
- 문의 폼
- **"주문 제작 안내"** 콜아웃 블록
- 이미지 처리: `.plate` 래퍼, 흑백

> **주의**: UI Kit의 컴포넌트 클래스명(`.btn`, `.card`, `.nav`, `.field`/`.input`, `.tag`, `.dialog`, `.table`)은 **디자인 원천의 어휘**다. 이 코드베이스에는 해당 컴포넌트 클래스 레이어가 **존재하지 않는다** — SPEC-DESIGN-001은 Tailwind v4 `@theme` 커스텀 프로퍼티 + 유틸리티 매핑으로 토큰화했고, `.btn`류 클래스를 만들지 않았다(grep 확인). 이 SPEC은 그 결정을 뒤집지 않는다.

> **사이즈 선택기 이탈**: UI Kit은 사이즈별 `disabled`를 전제하나, 이 SPEC은 사이즈별 재고 데이터를 갖지 않는다. 이탈의 근거와 대안 검토는 `plan.md` §B.1.
