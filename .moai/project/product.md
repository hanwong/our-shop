## 프로젝트 개요

- **프로젝트명**: our-shop
- **한 줄 설명**: 상품을 검색·구경하고 장바구니에 담아 결제까지 마칠 수 있는 모바일 우선(mobile-first) B2C 패션 온라인 쇼핑몰
- **도메인**: e-commerce-web (B2C 패션 온라인 쇼핑몰)
- **개발 형태**: 1인 개발(solo)

## 목표 (Goal)

고객이 모바일 브라우저를 포함한 어떤 화면에서도 편하게 상품을 둘러보고, 장바구니에 담고, 결제까지 마칠 수 있는 반응형 웹 쇼핑몰을 만든다. 회원가입 없이도 구매할 수 있는 게스트(비회원) 구매를 지원해 진입 장벽을 낮춘다.

## 타깃 사용자 (Target Audience)

- **일반 소비자(구매자)**: 패션 상품(의류, 잡화 등)을 온라인으로 구매하려는 B2C 고객. 모바일에서 주로 접속하는 사용자를 우선 고려한다.
- **게스트 사용자**: 회원가입 없이 빠르게 구매하고 싶은 비회원 고객.
- **쇼핑몰 운영자(관리자)**: 상품 등록/관리, 주문 처리 및 배송 상태 관리를 담당하는 내부 운영 인력(1인 운영 가능성 포함).

## 핵심 기능 (Core Features)

1. **상품 카탈로그 및 검색** — 상품 목록 조회, 카테고리/필터, 검색 기능. 응답 속도 p95 300ms 이하를 목표로 한다.
2. **장바구니** — 상품 담기/수량 변경/삭제, 게스트·회원 모두 지원.
3. **결제(PG 연동) 및 체크아웃** — 외부 결제대행사(PG) 연동을 통한 결제 처리. 결제 데이터 정합성을 최우선 품질 목표로 삼는다. 게스트 체크아웃을 지원한다.
4. **주문 및 배송 상태 조회** — 주문 내역 확인, 배송 상태 확인 (단, 외부 배송사 실시간 추적 API 연동은 이번 범위에서 제외).
5. **상품 리뷰** — 구매 고객이 상품에 대한 리뷰를 작성/조회.
6. **관리자 상품·주문 관리** — 관리자가 상품 정보를 등록/수정하고 주문 상태를 관리하는 화면.

## 범위 (Scope)

### In-scope
- 상품 카탈로그/검색
- 장바구니
- PG 결제 연동 및 체크아웃(게스트 포함)
- 주문/배송 상태 조회
- 상품 리뷰
- 관리자용 상품·주문 관리 화면

### Out-of-scope (현 단계 제외)
- 외부 배송사 실시간 추적 API 연동
- 멀티 벤더/마켓플레이스 기능

## 주요 사용 사례 (Use Cases)

1. **비회원 빠른 구매**: 방문자가 상품을 검색 → 상세 페이지 확인 → 장바구니 담기 → 게스트 체크아웃으로 결제까지 완료.
2. **회원 재구매**: 로그인 사용자가 이전 구매 이력을 참고해 재구매하고, 주문/배송 상태를 확인.
3. **상품 탐색 및 리뷰 확인**: 사용자가 카테고리·검색으로 상품을 탐색하고, 다른 구매자의 리뷰를 참고해 구매를 결정.
4. **운영자의 상품 등록**: 관리자가 신규 상품을 등록하고 재고/가격 정보를 관리.
5. **운영자의 주문 처리**: 관리자가 신규 주문을 확인하고 배송 상태를 갱신.

## 핵심 제약 조건 (Constraints)

- **결제 데이터 정합성 최우선**: 결제 관련 데이터는 어떤 상황에서도 어긋나서는 안 되며, 이는 다른 품질 목표보다 우선한다.
- **카탈로그 응답 속도**: p95 300ms 이하 (100번 요청 중 95번은 0.3초 이내 응답).
- **개인정보 최소 수집 원칙**: 꼭 필요한 개인정보만 수집하고 저장한다.

## 검증 방식 (Verification)

자동화 테스트(Jest/Vitest 계열)를 통해 신규 기능 추가 시마다 회귀를 자동으로 검증한다.

## 외부 연동 시스템 (External Systems)

- **결제대행사(PG, Payment Gateway)**
- **데이터베이스**

## 로드맵 후보 (다음 SPEC 후보)

인터뷰와 문서 검토 과정에서 드러난, 앞으로 `/moai plan`으로 구체화하면 좋을 후보들입니다. 아직 SPEC 문서는 만들지 않았습니다 — `/moai project`는 SPEC을 생성하지 않는 범위이며, 실제 SPEC 작성은 `/moai plan "<설명>"`으로 별도 진행합니다.

1. **결제(PG) 연동 SPEC** — 어떤 결제대행사를 쓸지, 중복 결제 방지(멱등키), 웹훅 기반 상태 확정, 결제 감사 로그 등 수락 기준(acceptance criteria)을 구체화. 결제 정합성이 최우선 제약이므로 가장 먼저 다룰 것을 권장.
2. **카탈로그 성능 검증 SPEC** — p95 300ms 목표를 어떤 도구·환경으로 측정하고 검증할지 정의.
3. **개인정보 처리방침 SPEC** — 실제 수집 항목, 보관 기간, 파기 정책 등 개인정보 최소 수집 원칙의 세부 사항 정의.
4. **인증/인가 SPEC** — 회원가입/로그인 방식, 관리자 권한 분리 방식 정의.
