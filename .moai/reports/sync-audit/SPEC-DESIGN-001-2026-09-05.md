## F1 Resolution — Re-verified

**Original finding (F1, CRITICAL, blocking)**: `body`'s pre-existing `font-family` rule in `globals.css` declared only the Korean-fallback stack (no Classical font reference), so every page element — which inherits from `<body>`, not `<html>` — never rendered Cormorant Garamond or Lora, despite `next/font/google` loading both in `layout.tsx`.

**Fix applied** (`src/app/globals.css`, verified by direct read of the current file):

```css
body {
  font-family:
    var(--font-body),
    ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto,
    "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif;
  line-height: 1.6;
  -webkit-text-size-adjust: 100%;
}

h1, h2, h3, h4, h5, h6 {
  font-family:
    var(--font-heading),
    ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto,
    "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif;
}
```

`--font-heading` = `"Cormorant Garamond", system-ui, sans-serif` and `--font-body` = `"Lora", system-ui, sans-serif` (declared in the untouched `@theme` block — confirmed byte-identical via `git diff a2b38fa..ae875b4 -- src/app/globals.css`, diff starts at line 65, the `@theme` block occupies lines 45-66).

**Re-verification performed (this pass)**:

1. **Cascade reasoning holds.** Read the current `globals.css` and `layout.tsx` directly (not inferred). `body`'s font-family now leads with `var(--font-body)`; a new `h1-h6` rule leads with `var(--font-heading)`. Both are element-selector rules with the correct specificity to apply directly (no longer relying on `<html>`-level `next/font` classes that never had any visible descendant effect — `layout.tsx`'s own updated comment now correctly documents this mechanic).
2. **No other overriding rule exists.** `grep -rn "fontFamily\|font-family" src --include="*.tsx" --include="*.ts" --include="*.css"` → only `src/app/globals.css` (the two rules above) and comment-only mentions in `layout.tsx`/`globals.css`. `find src -name "*.css"` → `globals.css` is the only CSS file in the project. No component sets an inline `style={{fontFamily: ...}}`. `SiteHeader.tsx` uses the pre-existing Tailwind-generated `.font-body` utility class (`grep -rln "font-heading\|font-body" src` → `layout.tsx`, `globals.css`, `SiteHeader.tsx`), which is consistent with — not competing against — the new rules.
3. **Regression test is genuine, not trivially satisfiable.** Read `tests/unit/app/typography-cascade.test.tsx` directly. Test 1 extracts the `body { ... }` rule via regex and asserts `font-family` matches `/var\(--font-body\)/` immediately after the `font-family:` token, plus the three Korean-fallback family names are still present. Test 2 strips the `@theme` block from the CSS text first, then asserts a `var(--font-heading)` reference exists **outside** that block — this specifically defeats a false-pass where the token is merely declared inside `@theme` (exactly what the original bug was) without being referenced anywhere else. Mentally reverting to the pre-fix `body` rule (no `var(--font-body)`, no `h1-h6` rule) would fail both assertions — confirmed by reading `progress.md §E.2`'s recorded RED output, which shows exactly these two assertions failing against the pre-fix file: `AssertionError: expected 'body {\n  /* A Latin stack...' to match /font-family:\s*\n?\s*var\(--font-body...`. Ran both tests independently this pass: `npx vitest run tests/unit/app/typography-cascade.test.tsx tests/unit/app/shell.test.tsx` → 11/11 pass (2 new + 9 existing shell tests, confirming no interaction regression).
4. **Korean fallback is unchanged.** Both the `body` rule and the new `h1-h6` rule carry the identical, unmoved 3-font Korean chain (`"Apple SD Gothic Neo"`, `"Malgun Gothic"`, `"Noto Sans KR"`) immediately after the Classical `var()` reference — verified in source and independently confirmed present, byte-for-byte, in the compiled production CSS (`.next/static/css/5c80d98d05cb2212.css`): `body{font-family:var(--font-body),ui-sans-serif,system-ui,-apple-system,"Segoe UI",Roboto,"Apple SD Gothic Neo","Malgun Gothic","Noto Sans KR",sans-serif;...}`. Korean copy carries no Cormorant Garamond/Lora glyph coverage, so it transparently falls through to the same curated stack exactly as before the fix — no new mechanism, no regression.
